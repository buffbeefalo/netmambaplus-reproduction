Lesson 01 · 00:00–02:00

The paper and the purpose

Plan: 90 seconds reading + 30 seconds practice and answer review

A packet is one small network message. A flow groups related packets into a conversation. An intrusion detection system (IDS) observes traffic and raises alerts. A classifier assigns categories; capture, alert rules and blocking require additional components.

The NetMamba+ paper combines bytes, packet sizes and time gaps: three views, or modalities. Mamba processes a sequence by updating a numerical state. The earlier NetMamba used bytes alone.

This repository records a reproduction attempt on an NVIDIA GB10 GPU: native builds, short pretraining, three full fine-tuning runs and saved-model inference worked. A GPU accelerates many numerical operations in parallel.

Lesson 02 · 02:00–06:00

Three files, two different kinds of data

Plan: 180 seconds reading + 60 seconds practice and answer review

The supplied PDF describes the research, not a ready-to-use dataset. The supplied CICIDS2017 CSV contains 1,410,255 packet rows and 15 labels. The UNSW CSV contains 79,881 packet rows and 10 labels. Each has 1,500 payload-byte columns plus TTL (remaining network hops), total length, protocol, time delta and label.

Neither CSV establishes connection identity and ordering. Adjacent rows cannot be assumed to form one conversation. The CICIDS2017 scan also found negative time deltas, with timing units unestablished. UNSW is a separate packet export, not a second native flow split. These were metadata profiles, not training runs or exhaustive payload validation. Training directly on them would create a packet-classifier adaptation.

For the original model, we acquired the authors’ processed CICIoT2022 flow release. CICIoT2022 and CICIDS2017 are different datasets. There are 8,323 training, 1,040 validation and 1,041 test flows. Training examples teach weights; validation chooses a checkpoint; the test split measures that selected model.

Native fieldMeaning
dataStored packet-byte sequences
sizesPacket lengths in sequence
intervalsTime gaps in sequence
label / class mappingKnown category / meaning of each class index

The six class indices mean 0 Flood, 1 RTSP Brute Force, 2 Audio, 3 Other, 4 Cameras and 5 Home Automation. The last four are IoT device/power categories. A compatible JSON file must preserve the native structure and preprocessing assumptions; similar column names are insufficient. IoT means Internet of Things: connected cameras and home devices. Flood overwhelms with traffic; RTSP brute force repeatedly tries access to a streaming protocol.

Lesson 03 · 06:00–10:00

How the model learns and predicts

Plan: 180 seconds reading + 60 seconds practice and answer review

The original loader takes five packets, each with up to 320 stored bytes: 1,600 values. The paper’s packet layout is 80 header bytes plus 240 payload bytes. Released flows already contain this extraction; our wrapper does not reconstruct headers from the uploaded CSVs. Bytes are scaled to [-1, 1]. The loader also pads or truncates the first 20 sizes and 20 gaps.

Sizes are clipped to 0–1,500; the size padding value 1,501 is clipped to 1,500. A finite nonnegative gap x becomes (1+x)/(2+x); padding infinity maps to 1. For classification, four-byte groups yield 400 byte tokens. Add 20 size tokens, 20 gap tokens and three summary tokens: 443. Four Mamba blocks process them; the three summary vectors are added before classification. Internal state belongs to this input computation, not an implemented live connection cache.

StageInput → operation → output
PretrainingUnlabeled flow features → reconstruct masked features → learned encoder
Fine-tuningFlows plus labels → update encoder/classifier weights → six-class checkpoint
InferenceFlow features plus frozen checkpoint → forward calculation → six logits and a selected class

Pretraining hides 90% of byte strides and 15% each of sizes and intervals in the source preset. A loss measures training error; the optimizer changes weights to reduce it. An epoch passes through the training loader. Our short pretraining check completed 132 updates. The three full fine-tuning runs instead began from the authors’ released pretrained checkpoint. They did not use that short-check checkpoint.

Logits are raw outputs. Softmax normalizes them into display scores. Labeled evaluation compares predictions with known answers to compute accuracy. Unlabeled prediction has no known answers and therefore cannot report accuracy. A successful manifest or export provenance binds the checkpoint to its class meanings; six output numbers alone do not identify those meanings.

Fine-tuning updates weights. Validation selects the checkpoint. Inference freezes it; known test labels are used afterward for scoring, not model selection or prediction inputs.

Lesson 05 · 13:00–17:00

What actually ran, and what the numbers mean

Plan: 150 seconds reading + 90 seconds practice and answer review

All three declared seeds completed 120 fine-tuning epochs and 7,920 updates each. A seed controls random choices; the three seeds used the same dataset split. Checkpoints were selected by validation accuracy, then strictly reloaded for test inference. All three results were retained.

ResultTest accuracy
Seed 091.26%
Seed 184.05%
Seed 284.63%
Mean86.65%
Paper, different conditions97.50% — not reproduced

The sample standard deviation is 4.00 percentage points, not a confidence interval. Accuracy is the fraction correct. F1 balances precision and recall; macro F1 treats classes equally, while weighted F1 weights their support. A confusion matrix exposes which true categories were confused with which predictions.

Source-based training used batch 128 and an effective learning rate of 0.001 on GB10; the paper describes batch 64, rate 0.002 and A100 hardware. The released checkpoint’s full pretraining history is unknown. Short reconstruction pretraining worked, but the paper’s full 150,000-step pretraining was not repeated. The cause of the accuracy gap has not been isolated.

Five raw-input overlaps were found between training/validation and six between training/test. Physical independence and original pretraining exposure remain unestablished. Rechecking the same test set demonstrates repeatability, not independent validation. GPU numerical checks and saved-model agreement support execution correctness, not operational detection accuracy.

Lesson 08 · 25:00–27:00

From classifier to IDS and accelerator

Plan: 90 seconds reading + 30 seconds practice and answer review

A live IDS would need capture → connection grouping → compatible tensors → inference → calibrated alert policy → analyst review. The source extractor has hardcoded paths and a missing helper; a compatible live pipeline has not been established.

A SmartNIC or DPU could steer packets and prepare flows. A GPU or supported neural processing unit (NPU) could classify them. This is a proposed division of work. Eager GPU inference works, but tested Torch graph capture failed at a custom causal-convolution operator. Saving model-only weights did not solve graph export. No NPU compiler or SmartNIC deployment was tested.

The model-only batch-one median was about 0.88 ms, excluding capture, flow waiting, preprocessing and transfers. It is not end-to-end IDS latency. The paper’s online throughput example concerns byte-only NetMamba. Next work includes independent traffic, extraction compatibility, alert calibration, export/operator support and inherited data/code rights.
